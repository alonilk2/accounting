# Backlog: תוכנית תיקון מבנה אחיד (INI.TXT + BKMVDATA.TXT)

## מטרה
להביא את ייצוא המבנה האחיד להתאמה מלאה לסימולטור מס הכנסה, כולל תיקון פורמט הרשומות, קשרי אב-בן בין רשומות, שדות חובה, וסגירה עם בדיקות אוטומטיות שמונעות רגרסיות.

## היקף
- כולל: `backend/Services/Compliance/ComplianceExportService.cs`, DTO/מודלים רלוונטיים, ולידציות, טסטים, ותיעוד.
- לא כולל: בלימה מיידית של היצוא הקיים.

## עקרונות עבודה
- קודם מתקנים תאימות פורמט וולידציות קריטיות.
- אחרי זה מיישרים מודל נתונים והגדרות חסרות.
- לבסוף סוגרים עם טסטים מקיפים ו-CI.

## Epic 1: שכבת סכימה ופורמט תקני

### Item 1.1: הגדרת סכימת רשומות קשיחה
- תיאור: להגדיר סכימה מרכזית לכל רשומה (`A000/A100/B100/B110/C100/D110/D120/M100/Z900`) כולל שדות, אורכים, טיפוסים, חובה/רשות.
- תוצרים:
  - מחלקות schema ב-`backend/Services/Compliance/Schema/`.
  - טבלת מיפוי פנימית: שם שדה -> מיקום/אורך/פורמט.
- DoD:
  - כל רשומה מכוסה ב-100% שדות לפי הסכמה.
  - יש בדיקה אוטומטית שמוודאת אורכי רשומה.

### Item 1.2: כתיבת formatters תקניים
- תיאור: לממש formatter אחיד לטקסט/מספרים/תאריכים/שעות/סכומים לפי דרישות סימולטור.
- תוצרים:
  - `TextFormatter`, `NumericFormatter`, `DateFormatter`, `AmountFormatter`.
  - איסור על ערכים אלפאנומריים בשדות מספריים.
- DoD:
  - אין כתיבת `decimal` בפורמט שאינו תקני בשדות מספריים.
  - כל formatter מכוסה unit tests.

### Item 1.3: תקנון קידוד ו-line endings
- תיאור: לאכוף קידוד ותווי שורה תקניים לכל הקבצים המיוצאים.
- תוצרים:
  - יישום אחיד ב-`AddZipEntry`.
  - בדיקת regression ל-byte output.
- DoD:
  - תוכן הקבצים יציב בין הרצות.
